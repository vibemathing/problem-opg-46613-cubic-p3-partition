# Mathematical Reasoning Discipline v1

<!-- MATHEMATICAL_REASONING_DISCIPLINE_V1 -->

本标准是 ProblemContract 准入、数学候选生成、研究执行、独立验证和 Result 验收的强制纪律。机器策略位于 `governance/control-plane/mathematical-reasoning-discipline.v1.json`。任何 scoped `AGENTS.md` 只能收紧，不能删除或弱化本标准。

规范性顺序是：

```text
定义与范围冻结
  -> 可追踪依赖链
  -> 显式构造或 witness
  -> 反例压力测试
  -> 不变量
  -> 单调量与终止
  -> 极值 / 对称 / 概率检查
  -> 尺度与极端边界
  -> 可复查证据与诚实结论
```

这个顺序不是要求每个问题都使用所有方法，而是要求每一步显式说明哪些检查适用、已完成、失败或不适用，以及理由。不得用省略、直觉或模型置信度替代证明义务。

## 1. 定义与陈述先行

开始推导、构造、计算或形式化前，必须冻结并引用：

- 对象类型、定义域、记号和等价关系；
- 量词及其顺序、参数范围和依赖关系；
- 前提、允许公理、目标陈述与目标的精确否定；
- 边界情形、退化对象、空对象约定和规模参数；
- ProblemContract 版本、陈述摘要和来源忠实性差异。

发现歧义时必须建立澄清义务并停止依赖该歧义的后续推理。不得静默扩大定义域、交换量词、加强前提、减弱结论，或把来源的 `open/solved/answered` 标签写成数学结论。

## 2. 推导必须形成依赖链

每个非平凡主张必须能映射到一个 claim/obligation，并记录：精确结论、适用范围、直接前提、依赖节点、使用的方法、尚未闭合的缺口和可判定的验收条件。

- 引用定理必须核对原文陈述、版本、前提和变量对应；名称相同不等于可直接使用。
- 代数变形必须检查除零、符号、分支、收敛、极限交换和可逆性条件。
- 局部结论不得无桥接提升为全局结论；有限规模结论不得无统一论证提升到任意规模。
- `therefore`、`clearly`、`similarly` 和图形直觉不能隐藏未登记的证明义务。

## 3. 逻辑规则必须严格

### 数学归纳

标准归纳必须逐项出现：

1. 证明 base case；
2. 对任意允许的 `n` 假设 `P(n)`；
3. 仅使用允许前提推出 `P(n+1)`；
4. 说明覆盖的起点、步长和定义域。

强归纳、结构归纳和超限归纳必须显式给出对应的归纳假设与良基关系。验证若干有限样本、观察递推模式或检查到某个上界都不是数学归纳。

### 逆否与条件方向

逆否只可在待用蕴含已明确为 `P -> Q` 时使用对应的 `not Q -> not P`。必须保留同一量词、定义域和前提环境。

不得把以下推理当作逆否或有效否定：

- 从“没有观察到某个充分条件”推出目标不成立；
- 从 `P -> Q` 推出逆命题 `Q -> P` 或否命题 `not P -> not Q`；
- 把“缺少充分条件”表述为“缺少必要条件”；
- 在量词交换后声称逻辑等价。

## 4. 存在性与构造性声明需要 witness

声称“存在”时，应提供可检查的显式 witness、有限证书或生成算法，并逐项验证它满足冻结定义。若只证明非构造存在，必须标明所用原理及其不提供的算法性保证。

声称“正确、可实现、可扩展、可终止”时，必须分别给出：

- 正确性依赖链或证明义务；
- 可运行 artifact、输入输出契约和版本；
- 复杂度/资源上界与适用尺度；
- 终止依据和失败行为；
- 至少一个反例或负向测试面。

候选代码存在、编译成功、CI 通过或模型给出伪代码，都不自动证明上述性质。

## 5. 主动攻击候选

在润色证明前，优先寻找最便宜的决定性反例：

- 最小规模、零/一元素、退化和极端参数；
- 等号、边界、奇偶、符号、连通性和空集情形；
- 对称对象、随机实例、已知 obstruction 和相邻定义；
- 删除一个前提、改变一个量词、交换极限或缩放后的失败点；
- 能使关键引理刚好失效的最小反例。

有限枚举、随机测试、数值实验和 SAT/SMT 搜索只在其精确范围内提供支持。一个经过 statement-faithfulness 与 witness 验证的精确反例可以反驳对应全称命题；“没有找到反例”不能证明全称命题。

## 6. 不变量、单调量与终止

使用递推、归约、局部变换、搜索或算法时，必须分别说明：

- **不变量**：每一步保持什么，为什么保持；
- **单调量**：什么严格增减，在哪个序或度量中；
- **终止依据**：该序为何良基、下界/上界是什么、是否可能循环；
- **闭合桥**：终止状态为什么蕴含目标，而不只是“无法继续”。

局部改善、平均改善、启发式收敛或有限运行未超时，均不能替代全局终止证明。

## 7. 极值、对称、概率与尺度检查

适用时必须系统检查：

- 选择最小反例或极值对象后，极值量是否存在并与变换兼容；
- 对称性是否允许商去冗余，以及固定点/轨道是否遗漏；
- 双计数、平均值、期望、一阶/二阶矩或局部引理的前提是否满足；
- 概率存在性是否被误写成显式构造、算法成功率或高概率统一结论；
- 小规模、渐近规模、稀疏/稠密、局部/全局、连续/离散之间是否有明确桥接；
- 极限、紧致性、选择原理或完备性是否被隐式使用。

方法不适用时记录原因；不得机械套用术语制造完成感。

## 8. 可验证证据与结论边界

每个 candidate 至少保存：稳定 ID、精确主张、依赖、假设、方法、适用范围、反例攻击结果、未决义务、artifact/source locator、内容摘要和证据天花板。

- 计算回执必须绑定输入、代码、命令/方法、精确版本、资源/时间/输出限制、退出状态、输出摘要和局限。
- 形式化回执必须绑定 theorem statement、toolchain、依赖、axiom/escape audit；kernel check 不替代 statement-faithfulness。
- 文献证据必须绑定可定位原文、版本、引理/定理编号、前提映射和引用归属。
- generator 自检、有限测试、PR、review、merge、CI、checkpoint 或运行结束都不是独立数学 Evidence。
- 未实际执行的工具计划必须标记 `pending/unverified`，不得伪造 stdout、exit code、digest 或 receipt。

只有可信 gate 可以从冻结 Candidate 与独立、适配能力且陈述忠实的 receipt 派生 EvidenceLink 和 Result。有限支持保持 `supported` 或 candidate-only；不得越级写成 `established`、`refuted` 或 `kernel_checked`。

## 9. 提交与验收清单

候选生成、验证请求、人工复核或 Result 验收前，必须逐项回答：

1. 定义、量词、前提、目标和精确否定是否冻结？
2. 每个关键结论是否有可追踪依赖和未闭合义务？
3. 若声称存在/构造，witness 是否显式且逐项验证？
4. 是否攻击过最小反例、极端边界和前提敏感性？
5. 不变量、单调量与终止依据是否分别证明？
6. 归纳和逆否是否按本标准使用，未以有限样本或条件方向错误替代？
7. 极值、对称、概率和尺度方法的前提是否核对？
8. 证据是否绑定精确陈述、artifact/source、版本、摘要、能力与局限？
9. 当前结论是否严格处于证据允许的层级？

任何必需项未满足时，输出应是明确的 open obligation、failed route、bounded candidate 或 `inconclusive`，而不是数学闭合。
